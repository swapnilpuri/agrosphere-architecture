# ADR 0012 — Rubber tapping operations

Status: Accepted for Milestone 3A, 2026-10-24.

Operations owns schedules, assignments, execution, missed reasons and outbox. Plain immutable Java aggregates enforce state transitions; application transactions coordinate a JDBC adapter and event persistence. Flyway owns DDL. No JPA mapping or cross-service persistence is used. Contracts are independently released and pinned into Operations resources.

Recurrence is deliberately limited to DAILY and EVERY_N_DAYS:n (1–999), anchored at effectiveFrom, with inclusive bounds and at most 366 days between requested endpoints. A schedule has one occurrence per date, assigned to one worker; generation is serialized with a row lock and protected by permanent schedule/date uniqueness. Repeating an occurrence with a different worker conflicts; use explicit worker reassignment while PLANNED. Cancelled occurrences stay cancelled and generation never resurrects them. Cancelled ad hoc work may be replaced. Noncancelled worker/block/date uniqueness includes terminal work to prevent duplicate execution.

Only DRAFT schedules are editable. Activation may resume SUSPENDED; CLOSED is final. Suspending/closing stops generation and leaves existing assignments intact. Assignment transitions: PLANNED → IN_PROGRESS/MISSED/CANCELLED; IN_PROGRESS → COMPLETED/MISSED/CANCELLED. Terminal states are immutable. Start creates the execution record; completion requires it and fills actual count and server completion time. Aborted executions retain their partial record for audit but never count toward actual completed trees. No latex weight or DRC is captured.

Every mutation carries the observed version. Conditional SQL updates prevent lost writes, returning 409 on conflict. Repeated successful start, completion, missed marking and cancellation return the persisted result without new events. Completion/missed retry payloads must agree; contradictory retries return 400. Schedule lifecycle retries to the current status are no-ops. Creates use new UUIDs; ambiguous create responses must be resolved by reading filters rather than blindly retried. Generation retries reuse permanent occurrences. Concurrent requests may receive 409 and should reload before retrying.

All audit instants use UTC. Tapping dates are ISO local business dates, never dates derived from the server timezone. Estate GET provides canonical timezone; block GET confirms active RUBBER ownership. Starting requires today's estate-local date; missed marking permits today/past only; no automatic missed-job exists. Completion may follow midnight for already started work. All HTTP validation calls delegate the authenticated bearer token, use trusted static base URL, no redirects, bounded connect/request timeout and fail closed (403 denied, 422 invalid/inactive reference, 503 unavailable). No fake dependency fallback or copied master metadata. The deployment must use TLS outside a trusted local network. Estate operational roles receive scoped master-data read access only.

PLATFORM_ADMIN and PLANTATION_ADMIN manage Operations globally. ESTATE_ADMIN/ESTATE_MANAGER manage scoped schedules/work; FIELD_SUPERVISOR manages scoped assignments; FIELD_WORKER sees/executes only assignments whose workerId matches JWT sub and estate_ids; AUDITOR/VIEWER read scoped work. Caller workerId never authorizes access. Keycloak estate_ids is administrator-managed. The existing PLATFORM_ADMIN remains the canonical master-data administrator; PLANTATION_ADMIN has global read validation but no Estate writes.

Summary planned assignments means all assignments in the inclusive tapping-date filter, including cancelled work. Completion percentage = completed/all ×100, rounded to two decimals, zero for empty sets. Planned trees sum all planned counts; actual trees count only completed execution records. Worker/block grouping uses current assignment ownership. Operations summaries are live SQL aggregations, not an analytics warehouse.

Outbox writes share the operational transaction. Relay selects committed rows FOR UPDATE SKIP LOCKED, publishes persistent messages to agrosphere.domain with agrosphere.EventType.v1, requires positive publisher confirmation and no mandatory return, then marks published. Stable eventId survives retries; capped exponential delay (max 3600s) and finite attempts retain FAILED rows. A crash after broker ack but before DB commit causes duplicates; consumers deduplicate by eventId atomically with their own writes. No exactly-once claim. Existing event schemas are byte-preserved; operations/v1 keeps established eventVersion/timestamp/source/provenance metadata plus aggregateId/version.

Recovery: fix routing/broker first, inspect failed event IDs without exposing payloads, then explicitly reset FAILED rows to PENDING and next_attempt_at=now() under an operator-controlled transaction. Never regenerate event IDs. Monitor operations.outbox.backlog/failed. Database update failures roll back the relay batch, preserving redelivery.

Real Keycloak acceptance found the existing custom default scope omitted the canonical sub claim. Add an explicit oidc-sub-mapper to agrosphere-api (access.token.claim=true); worker identity and recording actors always use signed sub, never username fallbacks. Existing realms need the additive identity configuration step. This follows the official [Subject mapper documentation](https://www.keycloak.org/admin-api/protocol-mappers#subject-sub).
