# Integration and data rules
REST/OpenAPI handles synchronous queries/commands. RabbitMQ carries asynchronous domain events. MQTT is device transport into telemetry only. Clients use gateway entry points; backend JWT validation remains independent. No service reads another database. No distributed database transactions or synchronous call cycles.

Canonical estateId and blockId are UUIDs generated only by estate. Spatial uses them as external references, never cross-database foreign keys. Geometry stays in spatial/PostGIS. Analytics and AI retain only service-owned projections/artifacts; they use APIs/events for upstream data. A missing external identity is retried/reconciled, never synthesized. GeoJSON follows RFC 7946 WGS84 [longitude, latitude]; explicit units and dataProvenance travel with observations/predictions.

Events use durable topic exchange agrosphere.domain and routing agrosphere.<EventType>.v1. Each logical consumer owns a durable queue and DLQ; versioned contracts define producers. Estate publishes EstateCreated, PlantationBlockCreated/Updated; operations publishes LatexCollectionRecorded, TappingActivityRecorded, CropHealthIncidentDetected; telemetry publishes SensorReadingReceived; AI publishes YieldForecastGenerated. Analytics/AI consume only needed events; spatial projects estate identity. EnvironmentalAnomalyDetected is reserved for a future telemetry contract, not yet defined.

Idempotency algorithm: in the consumer database transaction, INSERT processed_event(consumer_name,event_id) ON CONFLICT DO NOTHING RETURNING event_id. If no row returns, ACK the duplicate after transaction completion. Otherwise apply business/projection writes and commit; ACK only after commit. Any failure rolls back the marker and changes, then bounded retry/backoff. Poison events go to DLQ with correlation and reason. Consumer-name scopes allow distinct consumers to process the same event once each.

Outbox algorithm: domain mutation and serialized event are written in one local database transaction. A service-owned relay locks batches (FOR UPDATE SKIP LOCKED), publishes persistent messages with publisher confirms and only then sets published_at. Confirm/crash ambiguity creates duplicates, handled by consumers. Keep eventId stable across retries; partition/order by aggregate only where required and use revisions for stale updates. Acknowledge delivery after durable effects. TTL/retention, relay leases, retry budgets and replay tooling must be specified and tested with first handlers. M0 provides tables/design only, not working consumption or relays.

JWT issuer is configured without embedded secrets. Audience/estate-role enforcement and security regression tests are mandatory before domain routes. M1C implements gateway routing and a bounded per-process authenticated-subject limiter; ADR-0010 records the local-only policy. OpenTelemetry spans use W3C trace context and correlation IDs without logging credentials.

Milestone 1A update: estate publishes EstateCreated, EstateUpdated and PlantationBlockCreated/Updated using v2 routing and full entity snapshots (ADR-0008). V1 schemas are preserved; other producers remain v1 foundation designs. The estate relay is now implemented and container-tested. Spatial implements its v2 consumer in M1B; M1C verifies it with the real Estate publisher. V2 requires occurredAt/sourceService and retains explicit provenance and UUID identities. Retry budgets, retained FAILED records, replay and disabled-publication operation are documented in Estate Service README.
