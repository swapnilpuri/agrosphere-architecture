## Demonstrable increment and proposed rules

Target after those gates: one generated estate/block daily production history dashboard backed by Analytics-owned materialized storage, not live Operations SQL or browser summation. Inputs are the four already accepted Operations collection-v2 event types: Recorded, DrcMeasurementRecorded, Adjusted and Voided. Their full post-command collection snapshots and consumer rules are specified in the [accepted 3B event design](../../../agrosphere-contracts/docs/milestone-3b/API_EVENT_DESIGN.md). Preserve every existing producer/API/event byte. Do not consume legacy collection-v1 or infer missing DRC.

| Decision | Proposed bounded behavior |
|---|---|
| Source and grouping | Canonical estate/block plus immutable snapshot `collectionDate` (estate-local day already determined by Operations); never derive day from delivery time, browser timezone or `tappingDate`. Preserve snapshot timezone. No worker/division drill-down, attendance, per-tree/per-hectare yield or productivity denominator |
| Provenance | SIMULATED-only preparation/demo; never merge REAL and SIMULATED. A valid REAL envelope is unsupported for this generated consumer, quarantined visibly with zero KPI contribution; no silent relabelling |
| Contributions | Latest nonvoid collection contributes wet latex mass. Pending contributes pending count/mass and no invented dry mass. Calculated contributes count/mass plus the producer's rounded `dryRubberKg`. Void retains highest-version tombstone, contributes void count and zero active mass. Sum rounded collection dry values exactly, matching accepted `SUM_ROUNDED_COLLECTION_KG_V1`; do not sum `dryRubberExactKg` and round once |
| Numeric and coverage semantics | Decimal arithmetic end to end; mass fields exposed as decimal strings in the new candidate. Include active/pending/calculated/void counts, wet/calculated/pending wet mass, known dry mass and `isComplete` (pending count zero), labelled collection-DRC coverage only. Do not imply complete broker history, measured plantation coverage or accuracy. No weighted DRC/yield estimate in this first dashboard |
| Ordering/idempotency | Transactional processed-event record and projection update; ACK only after commit. Duplicate event ID with identical validated content changes nothing; changed content for an existing event ID is conflict. Higher aggregate version replaces the previous contribution, reversing the old day if corrected. Lower version has no contribution. Equal version with different event/snapshot is conflict, never additive. Apply higher full snapshots received before creation while recording a visible version gap. Voids cannot be resurrected by old messages |
| Rebuild and evidence | Analytics retains only validated minimal collection contribution facts and source event ID/version/fingerprint, not worker identifiers, actors, notes or DRC evidence. Rebuild its daily materialization from its own retained highest-version ledger in a new fixture and compare an independent oracle. This proves materialization reproducibility, not recovery of missing upstream history; unresolved gaps/conflicts remain explicit. No indefinite raw personal-event archive or cross-service SQL |
| Read candidate | Propose one Gateway-only GET daily history route for one explicit estate/block and inclusive from/to dates, bounded at 367 dates (same 3B convention). Sorted ascending, explicit generatedAt/projection policy/provenance/source versions and gap/conflict state; no-data days distinguished from known pending data. Exact shape/statuses/examples and absence semantics are reviewed in the executable candidate before release. No public rebuild/write route |
| Access | JWT signature/issuer/audience/lifetime plus explicit canonical estate scope before any query; platform/plantation administrators globally, assigned estate administrators/managers and auditors read only. Supervisor/worker/viewer excluded for this production-summary increment unless explicitly reviewed. Existing roles only, no widening of other feature permissions. Use delegated Estate checks for active block ownership; dependency failure is unavailable, never an empty total |
| Operations and UI boundary | Eventual projection, not synchronous source confirmation. Show last processed/source freshness, gaps/conflicts/unavailable and SIMULATED limits. New queue/limits/runtime log-minimization/retention and ephemeral-copy teardown need adapter review before use. No MQTT-derived environment correlation, AI inference, assistant, offline persistence or French implementation in this increment; those retained requirements follow their existing dependencies |
