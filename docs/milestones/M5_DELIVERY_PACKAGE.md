## API and security design for review

Current Contracts repository version is independent from per-document versions. Estate document 0.2.0 SHA-256 `2e7a0b028d91f9f2996289955d52d84e14d65e813582ade46772e59cd504a060`; Spatial document 0.3.0 SHA-256 `ca853e9ff9e8f8b752854ceaaf001622490b2a089478757320c356d15b301f74`. These are also the exact Web pin hashes. Preserve them; copy released artifacts into Immersive only after package approval, never import sibling source at build/runtime.

| Actual operation | Consumed response / purpose |
|---|---|
| GET /api/v1/estates | EstatePage: content/page/size/totalElements; authorized estate picker |
| GET /api/v1/estates/{id} | Estate detail |
| GET /api/v1/estates/{estateId}/blocks | PlantationBlockPage; identity/metadata list |
| GET /api/v1/blocks/{id} | PlantationBlock; selected details |
| GET /api/v1/spatial/estates/{estateId}/features | FeaturePage; canonical geometries/provenance |
| GET /api/v1/spatial/blocks/{blockId}/geometry | Feature; selected geometry agreement/revalidation |

Follow current query parameters/page constraints, not invented envelopes. Match estateId and referenceEntityType=BLOCK/referenceEntityId to Estate block id; spatial Feature.id remains a separate identity. Accept only finite, valid bounded coordinates and closed Polygon/MultiPolygon rings including holes; distinguish missing geometry from an empty estate and transport failures. Geometry versions and IDs must agree between bulk and selection requests; discard stale asynchronous completions after estate/session changes. Never render an unauthorized or mismatched object. No writes from Immersive; GET retries are side-effect free and need no invented idempotency key. Fixture creation uses existing service API semantics and owned run identities, not cross-service SQL.

Map 400 malformed request, 401 expired/invalid session, 403 denied, 404 missing, 409 conflict and Spatial 413 too large using current Problem envelope. Handle Gateway 429/Retry-After, 5xx, timeout and unreachable distinctly; no automatic 401/403 retry loop. One in-flight session refresh, at most two transient GET retries with bounded backoff and user cancellation; ten-second request deadline. Loading/empty/denied/unavailable/unsupported/ready are visible. Clear protected scene/details on logout, token expiry or denial; transport failure hides protected view until successful revalidation. No offline data access. Cancel requests on session change and reject late results.

Proposed fixture login: bind exclusively 127.0.0.1:49152 `/oauth/callback` before opening browser, exact registered redirect (no wildcard), fail visibly on occupied port. Random PKCE verifier/state/nonce from OS crypto; single-use transaction and callback, five-minute login timeout. Validate response state and issuer, ID-token signature/audience/nonce/expiry with a reviewed OIDC implementation; never trust decoded-only JWTs. Tokens stay in process memory, refresh before expiry, refresh failure clears state; zero references/stop listener on logout/cancel/shutdown. No offline_access. Bound session to 30 minutes in fixture. Browser IdP session cleanup is separate and must be exercised. Local HTTP exception is loopback-only for this disposable POC; non-loopback endpoints require HTTPS and explicit authorization. Approved fixture audience mapping covers agrosphere-api, estate-service and spatial-service without widening role grants; scoped VIEWER and foreign-estate/denied test subjects are generated only.

## Scene, coordinates and measurable exits

Proposed reference scene: two generated estates (one denied), one authorized estate with 12 blocks, at most 100 features, 10,000 total vertices and 2,000 instanced illustrative trees. Maximum 10 MiB aggregate decoded geometry, 100 items/page and 100 pages; overflow fails explicitly rather than displaying an apparently complete truncated estate. Keep parser/transport ceilings consistent; validate fixtures against actual schemas. No extrapolation to arbitrary estate scale.

Use WGS84 -> ECEF -> Cesium local frame -> Unreal centimetres; pin origin metadata with the generated fixture. Test both hemispheres, longitudes near +/-180, high latitudes, holes/multipolygons, NaN/range errors, large ECEF values and multiple origin changes. Polar/antimeridian fixtures can be explicitly unsupported for rendering but must fail visibly; no silent deformation. Required generated local estate vertices round-trip within 1 cm, equivalent Web/ECEF vertices within 1 cm, and origins moved 100 km preserve canonical coordinates and selected UUID. This is numerical tolerance, not survey accuracy. Check metre-to-centimetre conversion and a 1 m reference object; distinguish physical world scale from overview scale. Rebase/recenter must not move the VR camera unexpectedly.

Exit requirements (all remain unexecuted):

1. Exact licensed editor/plugin/compiler combination compiles and launches actual editor; package Windows client, launch independently without editor and retain build/package identities/logs. Update foundation-only validator deliberately alongside implementation.
2. External-browser login, loaded generated estate, Web and Unreal selection of identical block UUID, geometry/source/version/provenance details. Record API DTO checksums, selected IDs, scene settings and screenshots without tokens.
3. Invalid issuer/audience/expiry, wrong role/estate/object, logout, callback state mismatch/replay, refresh failure, cancelled requests, offline API, malformed/oversize geometry, no geometry, empty estate and recovery all exercised. Confirm no token persistence or unauthorized scene residue.
4. Coordinate and origin criteria above pass automated tests and actual client comparison. Pure tests alone cannot prove renderer agreement.
5. Named PC at 1920x1080 desktop: proposed p95 frame <=33.3 ms and useful estate view <=10 s after successful login on the local fixture. Record CPU/GPU/RAM, resolution, build/settings and cold/warm timing separately. These do not close M2's separate gate.

Tester may stop immediately; incomplete or uncomfortable run is not a pass. Desktop simulation cannot satisfy this exit.
7. MR report names supported/unknown capabilities and alignment error sources; no numerical field accuracy without measured ground truth. VR positional tracking does not establish plantation geospatial alignment. Record prerequisites for a later independently authorized MR trial.
