## Acceptance evidence and release gate

Implementation is accepted only after every AC has current passing evidence or an explicitly reviewed scope change. Required artifacts: domain/access/HTTP/JDBC test reports, migration/rollback results, real broker envelopes and retry assertions, runtime OpenAPI comparison, independent Docker build logs, disposable-stack acceptance report, old-contract hash comparison, diagrams and a final repository change inventory. Record failures and unavailable checks plainly. Unit tests alone do not prove broker, DB or identity behavior. Historical 3A completion is a baseline, not a substitute for current regression. Design review cannot be represented as implemented/accepted 3B. No remote CI/deployment or production-readiness claim follows from local tests.
