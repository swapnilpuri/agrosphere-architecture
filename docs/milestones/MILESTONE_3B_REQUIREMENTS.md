# Milestone 3B — Latex collection and DRC requirements

Status: ACCEPTED design by project owner, 2026-10-27 (America/Chicago), with R01/R02; see [owner approval record](MILESTONE_3B_APPROVAL.md). Implementation is authorized subject to dependencies/validation and independent contract review/release gates; no feature implementation or runtime acceptance is claimed.

## Scope and baseline

FR-04 is partially delivered by tapping-only 3A. This increment adds collection mass, measured DRC and calculated dry rubber inside Operations. It excludes pooled multi-execution loads, inventory/sales/payment, laboratory integration/certification, instruments, Analytics projections, Web consumers, inspections and IoT. The orchestrator and its persisted run remain paused and untouched. Milestone 2's reference-device FPS/useful-view performance acceptance gate remains open; backend 3B planning does not close it or declare the earlier sequence complete.

Read [design](MILESTONE_3B_DESIGN.md), [implementation plan](MILESTONE_3B_IMPLEMENTATION_PLAN.md), [acceptance criteria](MILESTONE_3B_ACCEPTANCE_CRITERIA.md), and [proposed ADR 0013](../adr/0013-latex-collection-and-drc.md). Proposed wire contracts live in the owning [Contracts repository](../../../agrosphere-contracts/docs/milestone-3b/API_EVENT_DESIGN.md). ADR 0012 remains accepted and unchanged.

## Business vocabulary

A tapping execution is an existing TappingRecord linked one-to-one to TappingAssignment. A collection is one separately weighed physical lot from exactly one completed execution. Wet latex mass is the net latex mass in kg, excluding container tare. DRC is a reported dry rubber content percentage for a sample of that lot; capture is an assertion with provenance, not proof of a laboratory method or certified result. Dry rubber kg is a deterministic derived quantity, not an independent observation. Worker attribution is the execution's worker (signed identity subject), whereas collector/recorder is an audit actor; these may differ.

## Functional requirements

| ID | Requirement and observable rule |
|---|---|
| B3-01 | Create a collection referencing an existing record whose assignment is COMPLETED and completedAt is present. Reject PLANNED/IN_PROGRESS/MISSED/CANCELLED and partial aborted records. Copy immutable execution UUID, assignment UUID, worker, estate, block and tappingDate from Operations, never from request identity fields. Zero actual-tree executions cannot receive positive collections in this increment. |
| B3-02 | Require collectedAt as an offset-bearing timestamp; normalize to UTC microsecond precision. Derive collectionDate from collectedAt in the canonical estate timezone obtained at creation; persist that zone and date. Require completedAt <= collectedAt <= server receivedAt and collectionDate >= tappingDate. No assumed clock-skew allowance. measuredAt may be later than collection. recordedAt is a server UTC instant and never a replacement for observed time. |
| B3-03 | Permit several disjoint weighed lots per execution; require a stable collectionReference supplied by the recording process. Uniqueness is execution + normalized reference and survives voiding. No uniqueness on execution/date and no silent addition or replacement of weight. No quantity cap inferred from tree counts. Separate references cannot detect the same physical lot automatically; operators reconcile suspicious duplicates. |
| B3-04 | Require positive net wetLatexKg, at most 999999.999 kg, at most 3 fractional digits. Reject zero/negative, nonfinite, out-of-range and excess nonzero fractional precision. Zero yield is already representable as execution with no collection; no fabricated zero collection. |
| B3-05 | Initial collection has no DRC. Append a measurement with 0 <= drcPercent <= 100, at most 2 fractional digits, measuredAt >= collectedAt and <= server now, method and sourceReference. Zero is an explicit measurement, distinct from missing. No default/estate average, copied measurement, estimate or prediction substitutes for a missing observation. |
| B3-06 | Compute dryRubberKg = wetLatexKg * drcPercent / 100 using decimal arithmetic, round HALF_UP to 3 places. Missing DRC means dryRubberKg=null and PENDING_DRC. Preserve input revision and calculation policy. Never label derived quantity laboratory-certified. |
| B3-07 | Capture weight source, DRC method/source, measurement time, recorder and optional instrument/sample references. REAL and SIMULATED are allowed observed-data provenances. Preserve historical observations and provenance independently; do not blend simulated and real quantities. ESTIMATED/PREDICTED remain platform vocabulary but are rejected for these observation endpoints. |
| B3-08 | Managers may atomically approve/apply a reasoned correction to wet mass, collectedAt, weight evidence, or replacement DRC. Preserve before/after snapshots, old measurement, signed actor, server time, reason and expected version. No in-place overwrite of evidence, physical deletion, reopening or mutation of 3A. Wrong execution/ownership requires void then create a replacement with a new reference and replacementOfCollectionId. |
| B3-09 | States are PENDING_DRC, CALCULATED, VOIDED. Initial measurement changes PENDING_DRC -> CALCULATED. Approved adjustment preserves/recomputes state; moving collection time past current measuredAt requires an atomic replacement measurement. Void is terminal, requires reason, retains evidence and removes current contribution from summaries. No automatic finalization or hidden transition. |
| B3-10 | Every mutation requires a durable Idempotency-Key. Non-create commands also require observed collection version. Successful retries return the original command result, create no history/event and do not fail solely because later commands advanced version. Same key with different normalized command conflicts. Concurrent stale writers return 409; exact-once delivery is not promised. |
| B3-11 | Enforce JWT issuer/audience/signature/lifetime, trusted estate_ids and signed sub at service and gateway. Estate/block come from execution. Workers create/read own scoped execution collections; supervisors record/read scoped collections and initial DRC; estate managers/admins approve adjustments/voids. Read-only roles never gain write permission. All object, history, query and summary access has scope predicates before pagination or aggregation. No independent block claim exists; restriction means execution block must belong to the trusted estate. New finer block entitlements require another security design. |
| B3-12 | Provide bounded live summaries grouped by total, estate, division, block, worker or collectionDate, using immutable attribution snapshots. Exclude VOIDED from quantities; report void count separately. Distinguish pending wet mass/count from calculated wet mass/count and known dry kg, retain missing DRC coverage. Group by provenance as a mandatory dimension; never report partial known dry mass as full production. |
| B3-13 | Map invalid syntax/range/transition to 400, unauthenticated 401, forbidden 403, unknown local record 404, version/reference/idempotency conflict 409, invalid Estate master reference 422, unavailable/malformed master response 503. Use established ProblemDetail and correlation ID; rollback all writes on failure. Broker outages leave committed collection + pending outbox. No invented dependency or DRC success. |

## Decisions requiring business/architecture review

D01–D12 below were accepted together by the project owner on 2026-10-27; see [owner approval record](MILESTONE_3B_APPROVAL.md). The table preserves the reviewed recommendation/consequence wording as the decision rationale. Production deployment and secret-handling changes remain unauthorized.

| Decision | Recommended default | Consequence / alternative requiring a revision |
|---|---|---|
| D01 Eligible execution | Completed, nonzero actual trees; collection after execution completion | Collecting during tapping or pooled collections needs changed eligibility/allocation model. |
| D02 Repeated collections | Distinct physical lots, permanent execution/reference uniqueness | Reference allocation is an operator/device responsibility; different references can still describe a duplicate physical lot. |
| D03 Time/backdating | No future observation; unlimited historical entry with reason for prior estate-local days | Workers may enter own historical collections with reason; a business cutoff/manager-only backdating requires review. |
| D04 Bounds/precision | Wet 0.001..999999.999 kg; DRC 0.00..100.00; dry kg scale 3 HALF_UP | These are software bounds, not agronomic expectations or instrument accuracy. |
| D05 Missing DRC | Persist pending with null dry kg; only direct lot measurements | Pooled sampling, defaults and estimated production remain excluded. |
| D06 Measurement authority | Management/supervisor may append first DRC; workers only record weight | No new laboratory role or integration. Imported lab claims are user-declared provenance, not verified certification. |
| D07 Correction approval | Estate manager/admin (global admins included) applies correction with reason in one transaction | Same-person recording and approval permitted. A four-eyes/pending-request workflow is outside this design and needs another state model if required. |
| D08 Historical grouping | Snapshot block division at first collection; execution worker is production attribution | Master-data reparenting never silently moves historical totals. No authoritative division-lifecycle claim. |
| D09 Evidence retention | Retain observations, revisions, idempotency results and events indefinitely for this increment | Production retention/privacy/access policy must be set before external deployment; no automated purge is designed here. |
| D10 Observation provenance | REAL or SIMULATED only, separate summary groups | Measurement provenance must equal collection provenance; changing provenance requires void/replacement. |
| D11 Lifecycle | Pending/calculated/voided; calculation is not financial approval | No payment-grade locking, stock ledger or certification. |
| D12 Recovery semantics | Stable keys retained, immutable history and explicit replay of failed outbox IDs | No automatic retry of ambiguous creates using new keys. |
