# AgroSphere 1A–3A acceptance reconciliation

Date: 2026-10-25 (America/Chicago). Scope: requirements, source and retained evidence review. This is an engineering assessment, not an authenticated approval or a fresh test certification. Only this report and its evidence index were created; application files, orchestrator state and recovered classifications were not changed. Nothing was published.

**Result:** local delivery of 1A, 1B, 1C and the tapping-only 3A scope is supported by code and historical execution evidence. **Milestone 2 remains PARTIAL because its performance exit gate is open. The next eligible acceptance work is Milestone 2 performance closure. 3B is the next feature-planning candidate, not an authorized implementation.** No documented dependency requires Milestone 2 rendering performance for backend-only 3B planning; a strict sequential declaration of all prior gates complete must wait for that closure.

## Assessment method and scope

Use the specific milestone scope and accepted ADRs before broad foundation backlog language, then trace each gate to implementation and executed evidence. Completion checkboxes, source/test counts, Git commit subjects and orchestration recovery observations alone do not prove acceptance. “Supported” below means the local scoped requirement has implementation plus retained historical results; current runtime behavior has not been freshly retested.

The recovered registry names the sequence **1A, 1B, 1C, 2, 3A, 3B**. There is no separate recovered 2A/2B specification; this audit does not invent one. Broad parent Milestones 1 and 3 must not be confused with their narrower increments.

Requirement sources: [milestone exit gates](../../roadmap/MILESTONES.md), [1A scope](../../roadmap/MILESTONE_1A.md), [1B scope](../../roadmap/MILESTONE_1B.md), [1C scope](../../roadmap/MILESTONE_1C.md), [functional requirements](../../requirements/FUNCTIONAL_REQUIREMENTS.md), [nonfunctional requirements](../../requirements/NONFUNCTIONAL_REQUIREMENTS.md), and [ADR 0012 / 3A scope](../../adr/0012-rubber-tapping-operations.md). Original user-request transcripts and a separately approved 3B specification were not recovered. Milestone 2's retained completion report documents functional DoD items 1–17 but does not reproduce the original full numbered specification; assessment uses the recoverable roadmap gate, implementation and report.

## Reconciliation findings

1. **Recovered PARTIAL is deliberately conservative, not a finding that every milestone failed.** [recovery_discovery.py](../../../../agrosphere-orchestrator/src/agrosphere_orchestrator/recovery_discovery.py) classifies observed implementation as PARTIAL and leaves verified criteria empty. [application-summary.json](../../../../agrosphere-orchestrator/docs/milestones/AEO-6/evidence/application-summary.json) therefore selects 1A for reconciliation while listing 3B as development_candidate. Its tests_observed counts are artifact observations, not numbers of executed test cases. This audit supplies the missing requirement mapping without modifying approval/runtime state.
2. **Historical evidence is corroborated, but freshness is limited.** Direct filesystem comparison found all 452 inventoried fingerprints unchanged from the recovery snapshot (observed 2026-10-25T23:54:46Z), and all 12 HEADs match. This proves consistency with that inventory only, not that every current file was inventoried or that old test outputs were generated from exactly those bytes. Git status could not be freshly executed. The snapshot's clean-state claim remains historical.
3. **Test counts reflect successive increments.** 1A originally reported 47 Estate tests; retained current XML has 48 because of 3A operational-role reads. 1C's 90 and 3A's later Estate/Gateway counts are not contradictory. Do not sum overlapping reruns as unique test coverage. Raw retained Java suites total 135 across the four relevant services (48 + 31 + 44 + 12), all with zero failures/errors/skips.
4. **Scope documents contain stale statements.** Foundation FR text still says all endpoints are future work; NEXT_CODEX_PROMPT still recommends already-delivered 1B; Operations AGENTS still says M0 and several other AGENTS scopes stop at 1C despite recorded 3A implementation. Treat them as stale planning/boundary metadata, not proof that source is absent or fresh authorization to proceed. No source instruction or roadmap file was rewritten during this review.
5. **Broad requirements remain open.** Company identity in FR-01 is not implemented by the narrowed 1A scope. Authoritative division lifecycle is absent. The proposed metadata p95 <500 ms at 20 concurrent users has no recovered benchmark; NONFUNCTIONAL_REQUIREMENTS calls these hypotheses, not achieved SLAs. Record this as M1-wide nonfunctional debt, not a fabricated pass or an automatic retroactive failure of every specific 1A–1C local exit gate. Reference-device visualization performance is an explicit M2 exit gate and does block full M2 acceptance.
6. **Toolchain and failed intermediate logs need context.** ADR 0009 already records the Estate Java 21/25 discrepancy; service-specific actual build/runtime evidence takes precedence over the old generic backlog Java target. The old Operations Python log records an openapi validator 0.8.0 dependency conflict; current requirements pin 0.9.0, consistent with the reported correction. The failed log itself is not passing contract evidence. Current contract/migration/diagram validators were not rerun here.
7. **Local acceptance is not production acceptance.** Hosted CI, production rollout, security/load SLAs, backup rehearsal and retained monitoring are not proven. Worker privacy/retention policy remains a product/deployment decision. Optional imagery/terrain/external hosts were not live-validated. These boundaries must remain explicit.

## Next eligible work

**First: close Milestone 2 acceptance.** Agree a named reference desktop/GPU, browser/version, representative estate and geometry/asset budget. Record repeatable cold/warm useful-estate-view times and interactive frame measurements during navigation, selection and layer toggles; retain browser/provider/configuration details, sample count and results against the agreed minimum 30 FPS target. The web report mentions a 10-second initial-view target; the original approved timing criterion was not recovered, so confirm that budget before treating it as a hard acceptance threshold. Choose a representative permitted terrain/imagery configuration and state which provider/fallback paths were exercised. Attach evidence and rerun the relevant functional checks before declaring full M2 acceptance. This audit does not implement or perform that work.

**Next new feature candidate: Milestone 3B, for requirements/design planning only.** The 3A report recommends 3B but does not define an approved specification. A reasonable proposed continuation is latex collection and DRC/dry-rubber calculation from FR-04, keeping explicit kg/percent units, validated ranges, immutable assignment/execution IDs, scoped roles, audit history, independently versioned contracts and idempotent events. That proposal must be scoped explicitly; incidents, MQTT/telemetry, Analytics projections and browser workflows are not implicitly included. No code start or delivery authorization follows from this reconciliation.

There is no recovered explicit dependency making M2 GPU performance a prerequisite for backend-only 3B planning. Accordingly, 3B planning can be eligible while M2 remains partial; advancing a strict sequential acceptance baseline or claiming all milestones through 3A fully accepted cannot. Fresh current-revision validation is still needed for a new formal acceptance/implementation checkpoint. This report leaves the existing 1A review candidate and approval state untouched.

## Checks performed and limits

Performed in this audit: read requirements/ADRs, relevant implementation and tests; parse 17 retained JUnit suite XML files; inspect 12 platform acceptance groups and the successful isolated 3A integration log; decode the embedded Playwright report (1 live test, expected outcome, zero skipped/errors); compare 452 snapshot hashes and 12 HEADs; hash 51 evidence artifacts; verify these generated artifacts and their local links.

Not executed: application builds/tests, Docker, live login, performance measurements, Git status/diff, Python validators or remote CI. The command tool failed with CreateProcessAsUserW access denied and the Node child-process fallback failed with spawn EPERM. Read-only filesystem analysis remained available. No unavailable check is represented as passed. Original ignored logs/results may be overwritten by later runs; the evidence index records hashes, not copies or cryptographically authenticated provenance.
